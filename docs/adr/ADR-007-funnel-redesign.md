# ADR-007 · 漏斗重构（保留漏斗 + 王败寇 + 薄肌王体感终层，砍分群运营）

- 状态：**Accepted**（PO 裁定，2026-10-22，经产品讨论 + AskUserQuestion 四项确认）
- 日期：2026-10-22
- 决策人：PO（产品所有者）；记录人：Tech Lead
- 关联：`product-definition.md` §15、`cloudbase-contract.md` §3、`ADR-006`（隐私冻结维持）

## 背景（Context）

PO 在 E2E 体验后给出产品反馈（2026-10-22）：
1. 看板很好；漏斗板块意义不明、不能突出转化；产品级 AARRR / 召回环不知道有什么用；分群运营觉得没用。
2. 经讨论澄清：PO **希望保留漏斗**（尤其是埋点模拟的转化展示），但要把产品级 AARRR **改名为「王败寇」**（社交证明向，展示"多少人在记录数据"），各层重命名并加阈值；薄肌王漏斗以**「自己体感（1–10 分）」为最终层**，各层记录真实数据、长期累积。
3. 力王 / 黄毛王漏斗本次**暂保留现有不动**；分群运营页**砍掉**（缺跨用户数据 + 无用户价值）；王败寇的"社区人数"用**占位数字**（不真做跨用户聚合，ADR-006 隐私冻结维持）；薄肌王第三层「压抑指标」作为**新增健康打卡类型 `suppression`**。

## 决策（Decision）

### 1. 漏斗机制保留
- 保留漏斗可视化（各步事件数、相邻步转化率 / drop-off / 瓶颈步）的**展示方式**——PO 认可埋点模拟的转化展示。
- 「王败寇」（原产品级 AARRR）继续基于 `analytics_events`（`product.*` 步骤）计算；薄肌王漏斗改为基于**用户真实打卡 `events`**（饮水/睡眠/运动/压抑/体感），以贴合"记录各层数据"。

### 2. 产品级漏斗改名「王败寇」（社交证明向）
目的：让用户看到"有多少人在记录数据"。五层重命名 + 阈值（基于 `product.*` 步骤映射）：

| 新层名 | 映射步骤 | 进入阈值 |
|---|---|---|
| L1 陌生人 | `product.acquire` | 进站 / 首触（base） |
| L2 好奇猫 | `product.activate` | 初步激活（完成首次打卡） |
| L3 留存 | `product.retain` / `product.habit` | **记录数据天数 > 3** |
| L4 落魄谷 | `product.habit`（深化） | **记录数据天数 > 10** |
| L5 少年归 | `product.value`（漏斗到达底部） | **漏斗到达底部次数 > 10** |

> 「社区人数」= **占位数字**（如「12.8 万人在记录」），**不实做跨用户聚合**；ADR-006 跨用户 cohort 冻结维持不变。若未来要真聚合，需另行升 PO 隐私合规裁定。

### 3. 薄肌王漏斗重构（最终层 = 自己体感 1–10 分）
基于真实 `events`（domain=health），四层：

| 层 | 数据来源（type） | 说明 |
|---|---|---|
| L1 喝大水和睡大觉 | `water` + `sleep` | 基础习惯 |
| L2 运动 | `workout` | 主动训练 |
| L3 压抑指标 | **`suppression`（新增）** | 越低越好：做了不想做的事 / 没做想做的事 → 下降值；随心所欲做了 → 上升值 |
| L4 体感（最终目的） | `body_sense.feel_score` | **自己体感打分 1–10** |

- 漏斗展示"用户离最终目的（体感达标）还差几步、每一层坚持得如何"，长期累积。
- `suppression` 为新增健康打卡类型（见契约 §3）；`body_sense` 增加 `feel_score: int 1..10`（替代/补充原 `feel` 枚举）。

### 4. 分群运营页：砍掉
- `pages/segments/index` 及其 tabBar 入口移除；`services/segments.ts`、`schemas/analytics.ts` 中分群相关逻辑清理（或保留函数但不再暴露 UI）。
- 理由：依赖跨用户数据（ADR-006 冻结），且 PO 确认无用户价值。

### 5. 力王 / 黄毛王漏斗：本次不动
- 维持现有行为漏斗（力王：启动→收入→支出→留存→推荐；黄毛王：启动→首触→破冰→约见→进阶→脱单→推荐）。后续可照搬薄肌王思路重构（PO 待定）。

## 契约影响（Contract Impact）

- **§3 health 域新增**：`suppression{score:int CHECK 0..10, note?:text}`（越低越好）。
- **§3 health `body_sense` 扩展**：增加 `feel_score?:int CHECK 1..10`（自己体感 1–10 分）；
- **§8 `step` 枚举**：薄肌王行为漏斗不再依赖 `health.*` 埋点步骤，改为由真实 `events` 的 `type` 推导；`product.*` 步骤维持（供王败寇）。`health.onboard`/`health.active_day` 等埋点步骤可保留但前端不再用于薄肌王漏斗可视化。
- **零数据库迁移**：`events.type` 为自由 text、`payload` 为 jsonb，新增 `suppression` 类型与 `feel_score` 字段均无需改表；仅改契约文档 + 前端注册表，**Codex 零改动**。

## 实施（Implementation）

- **前端（DeepSeek）**：
  - 体验优化（已另发派发）：离开页面自动保存打卡草稿；感觉/体感类输入改拖条（slider）。
  - 漏斗重构：王败寇改名 + 五层重命名/阈值 + 占位社区人数；薄肌王四层漏斗（含 `suppression` 录入 + `feel_score` 拖条）；移除分群运营页与 tabBar 入口；力王/黄毛王维持。
- **后端（Codex）**：本 ADR 无需云函数改动（`getFunnel` 仍按 `product.*` 聚合王败寇；薄肌王漏斗改由前端基于 `events` 客户端聚合或复用 `getFunnel` 传 domain=health 的 type 分布）。如薄肌王漏斗需服务端聚合，由 DeepSeek 在派发中说明，Codex 视情况补 `getFunnel(domain=health)` 的 type 分布返回。

## 影响 / 风险

- 王败寇"社区人数"为占位数字，非真实数据——UI 需明确其为氛围展示，避免误导（不声称精确统计）。
- `suppression` 为新增概念，录入口径（0–10 越低越好）需在 UI 给清楚引导。
- 力王/黄毛王漏斗未重构，可能与薄肌王新风格不一致；属已知暂留，后续统一。

## 被取代 / 撤销

- 取代 `product-definition.md` §15 中"产品级 AARRR + 召回环"的命名与分群运营相关表述（见 §15 同步更新）。
- 不撤销 `analytics_events` / `profiles` 建表（王败寇仍需 `product.*` 步骤数据）。
