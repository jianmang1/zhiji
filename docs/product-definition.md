## 1. 产品定位
- **一句话**：执己是一款**新粗野风格、五维人格化（XX王）**的个人数据微信小程序，用游戏化评分 + 多 AI 意见，帮用户"先知己，再执己"。
- **形态**：微信小程序（Taro 4 编译，同源出 H5 网页）；**C 端上架分发**（非自用工具）。
- **Slogan**：先知己，再执己。
- **价值主张（Why not 备忘录/记账App）**：
  - 把抽象"自我记录"变成有反馈、有态度的**"王"养成游戏**——即时评分给认知反馈，LLM 给可执行规划。
  - 五维统一在一个产品里，而非 health/记账/习惯分 App 各记各的。
  - 粗野视觉 + 人格化"王"，对抗"精致风"审美疲劳，给记录行为本身赋予情绪价值。

## 2. 目标用户（C 端画像草案）
- 关注自我提升、愿意记录生活的年轻人（约 18–35 岁）。
- 对健康 / 搞钱 / 消费管理有诉求，但讨厌被说教、偏好张扬反叛的表达。
- 对"精致ins风"审美疲劳，被粗野/梗文化吸引。

## 3. 核心闭环（升级版）
```
采集（打卡某王热点，手动）
   → 沉淀（结构化 events，按王归属 domain+type）
   → 评分（规则引擎算该王评分，即时反馈）
   → 看板（五王评分总览 + 趋势）
   → AI 意见（generatePlan 调 LLM 生成可执行规划）
   → 执行反馈（次日再打卡，形成循环）
```

## 5. 评分系统
- 每个王**独立评分**（0–100 或等级制），由**规则引擎**计算（不依赖 LLM，稳定、即时、零成本）。
- 评分维度 = 该王热点数值 → 规则映射（例：睡大觉 ≥7h 满分、喝大水 ≥2000ml 满分、练薄肌 ≥30min 满分）。
- **算在何处**：建议前端实时算（打卡即见反馈），云函数/服务端作为权威存分并供看板聚合。*TODO 与技术契约对齐（见 §12）。*
- 等级命名（如 青铜王/黄金王？）TODO 由 PO 定。

## 6. AI 意见（多 AI 分析）
- **看板 + LLM 生成 plan**：`generatePlan` 云函数 v1 上线（Codex 已实现骨架，需接云端 LLM）。
- 输入：该王近期 events + 当前评分；输出：可执行规划意见（文本卡）。
- 与评分系统分工：评分=客观反馈（规则），AI意见=主观可执行建议（LLM）。

## 7. 视觉风格（新粗野主义 Neo-Brutalism）
- 特征：粗黑边框、硬阴影(offset 无模糊)、高饱和撞色、大号粗体无衬线、不圆角/少渐变、张扬反精致。
- 各"王"用**独立高饱和主色**，形成人格化辨识（薄肌王=？力王=？黄毛王=？待定色板）。
- *视觉术语以 PO 确认为准；若"新粗野风格"另有所指，以 PO 解释为准。*

## 8. 用户旅程（关键路径）
1. 微信授权登录（`cloud.auth`）。
2. 首页看板：五王评分总览 + 今日待打卡。
3. 点某王 → 打卡页（手动录入该王热点数值）→ **即时评分反馈**。
4. 看板趋势 + AI 意见卡（generatePlan）。
5. 执行 → 次日再打卡，形成闭环。

## 9. MVP 功能清单（MoSCoW）
- **Must**：微信登录、五王打卡录入（手动）、评分系统、看板总览、AI 意见(LLM)、各王人格化视觉。
- **Should**：趋势图、周/月报、评分等级动画。
- **Could**：导入能力（微信运动/支付凭证）、社交排行、王成就体系。
- **Won't(v1)**：复杂图可视化(ReactFlow)、实时流、Neo4j、多人协作。
