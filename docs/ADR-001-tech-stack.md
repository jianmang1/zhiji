# ADR-001 技术栈与架构定案

- 状态：提议（2026-10-19，PO + 我 双角色 brainstorm 阶段）
- 决策者：产品负责人（最终拍板）；我（PM/架构/QC/Tech Lead 起草与审核）
- 关联原则：专业化 > 通用化；明确"能/不能"；契约是唯一交流语言

## 1. 决策摘要

| 维度 | 决策 | 备注 |
|------|------|------|
| 前端框架 | Taro（React 语法）+ 编译到微信小程序 / H5 | 保住 Gemini 的 React/TS 技能栈，真小程序形态 |
| 前端 UI | Ant Design Mobile（或 Taro UI） | 小程序内 AntD 桌面版不可用，需移动组件库 |
| 状态管理 | Zustand | 按原定位 |
| 客户端路由 | React Router（Taro 适配） | 按原定位 |
| 表单校验 | Zod | 按原定位 |
| 图可视化 | ReactFlow（小程序不支持时降级为静态图/列表） | 小程序对 ReactFlow 支持有限，需验证 |
| 前端测试 | Vitest + Playwright | 按原定位 |
| 后端语言 | Python 3.11+ | 按原定位 |
| Web 框架 | FastAPI | 按原定位 |
| ORM | SQLAlchemy 2.0 | 按原定位 |
| 数据库 | PostgreSQL 12+（启用 JSONB） | 图分析用 networkx / SQL 递归 CTE |
| 图数据库 | Neo4j【暂缓】 | 触发条件见第 4 节 |
| 部署 | 公网云（小程序必需，HTTPS 可达） | 隐私缓解见第 5 节 |
| 交付节奏 | 全栈一次到位（受契约门禁约束） | Phase 0 先锁契约包再写码 |

## 2. 角色"能/不能"边界（契约基础）

- **Codex（后端）负责**：DB schema 与 migration；RESTful API；业务逻辑；数据访问层；单测/集成测试。
  **不负责**：UI 组件/样式、前端状态、客户端路由、浏览器兼容。
- **Gemini（前端）负责**：Taro 组件与布局；Zustand 状态；路由；数据可视化；Zod 校验；前端测试。
  **不负责**：DB 查询/schema、API 端点实现、服务端校验、认证逻辑（仅 UI 集成）。
- **我（四合一）负责**：执行计划、周集成 checkpoint、技术栈选型、DB 设计、API 合约、ADR、9 门禁评审、异常救火。
- **PO 负责**：业务需求、功能优先级、验收、全局方向、冲突裁决、技术方案接受/拒绝、context 与进度风控。

## 3. 质量门禁（9 项）

1. API 契约一致性：前端调用须匹配 OpenAPI spec，偏差判失败。
2. Migration 可回溯：每版 migration 须含 up/down，可回滚。
3. 单测覆盖率：核心逻辑 ≥ 70%（可据域调整）。
4. 关键路径集成测试通过：采集→落库→看板 端到端。
5. 类型安全：TS strict + Python type hints 开启。
6. 安全门：无硬编码密钥、输入校验、鉴权；敏感字段加密。
7. 性能预算：首屏 < 2s，API P95 < 300ms（约定值，可改）。
8. 契约变更须 ADR + 通知对方 Agent，禁止静默改接口。
9. 文档齐备：README、部署文档、数据字典。

## 4. Neo4j 暂缓与迁移触发条件

v1 用 PostgreSQL + JSONB 存关系边表；环路/多跳分析用 networkx 或 SQL 递归 CTE。
满足任一即启动 Neo4j 评估 ADR：
- 节点规模 > 10 万且多跳查询成瓶颈；
- 需要原生图算法（社区发现、中心性等）且 SQL 实现成本过高；
- 关系写入并发成为瓶颈。

## 5. 部署与隐私缓解

- 小程序前端必须公网 HTTPS，后端与 DB 部署公网云。
- 隐私缓解：传输 TLS；敏感字段（健康/消费金额）应用层加密或脱敏；最小化采集；后续评估"本地采集 + 选择性上云"混合部署。
- 风险：个人敏感数据出公网。接受前提为上述缓解落地并通过安全门（门禁 6）。

## 6. 备选方案（Considered Alternatives）

- 微信原生 WXML/WXSS：弃——浪费 Gemini 的 React 栈，需重写前端定位。
- 纯 H5 网页：弃——开发快但非真小程序形态，与"小程序"目标不符。
- 直接 Neo4j：暂缓——运维重，单用户早期偏过度工程。
- 全栈跳过契约直接并行：弃——违反原则三，内耗风险高。

## 7. 风险与缓解

- 公网个人数据隐私 → 加密/脱敏/最小化 + 安全门。
- 全栈并行内耗 → Phase 0 契约先行 + 周 integration checkpoint（门禁驱动）。
- Taro 对 ReactFlow/AntD 支持差异 → 前端起步即做技术可行性 spike。
